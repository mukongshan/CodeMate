## 一、树形历史：Entry

对应 [02-树形对话历史系统](../系统设计/02-数据与存储层/02-树形对话历史系统.md)、[12-存储层设计](../系统设计/02-数据与存储层/12-存储层设计.md)。

```python
# src/storage/models.py
from dataclasses import dataclass, field
from typing import Literal, Union, List, Optional
import uuid
import time

Role = Literal["user", "assistant", "tool"]

@dataclass
class ToolUseBlock:
    """assistant 消息里的一次工具调用请求"""
    id: str                 # 对应 LLM 返回的 tool_call id
    name: str
    arguments: dict

@dataclass
class ToolResultBlock:
    """打包进合成消息的一次工具执行结果"""
    tool_call_id: str
    content: str             # 已格式化为文本，供 LLM 消费
    is_error: bool = False

@dataclass
class Entry:
    """树中的一个节点，对应 LLM messages 数组里的一条 message"""
    id: str = field(default_factory=lambda: uuid.uuid4().hex)
    parent: Optional[str] = None
    lane: str = "main"                       # 创建归属标签，非路径信息（见 03 号文档 1.5 节）
    seq: int = 0                              # 全局严格递增序号，加载时校验
    role: Role = "user"
    content: Union[str, List[Union[ToolUseBlock, ToolResultBlock]]] = ""
    timestamp: float = field(default_factory=time.time)

    def to_jsonl_dict(self) -> dict:
        """序列化为 JSONL 一行的 dict，content 里的 block 需展开为普通 dict"""
        ...

    @staticmethod
    def from_jsonl_dict(data: dict) -> "Entry":
        """从 JSONL 一行反序列化，缺字段按第 12 号文档表格的必需性报错"""
        ...
```

**字段约束**（对齐 [12-存储层设计](../系统设计/02-数据与存储层/12-存储层设计.md) 第三节）：

| 字段 | 是否必需 | 备注 |
|---|---|---|
| `id` | 是 | `uuid4().hex`，避免 JSON 里出现连字符转义问题 |
| `parent` | 是 | 根节点为 `None`；不是 `""` |
| `lane` | 是 | 仅用于展示溯源，不参与树查询（见 [03](../系统设计/02-数据与存储层/03-Lane分支管理系统.md) 1.5.2 节） |
| `seq` | 是 | 由 `SessionStorage` 在 append 时统一分配，不由调用方传入 |
| `role` | 是 | 三值枚举 |
| `content` | 是 | `str`（普通文本）或 `list[ToolUseBlock \| ToolResultBlock]`（工具相关消息） |
| `timestamp` | 是 | Unix 时间戳，float |

**并行工具调用的打包规则**（对齐 [02](../系统设计/02-数据与存储层/02-树形对话历史系统.md) 2.2 节）：一次 assistant 回复里的多个 `ToolUseBlock` 属于同一个 `Entry.content` 列表；对应的多个 `ToolResultBlock` 同样必须打包进**下一个** `Entry`（role=`tool`）的 `content` 列表里，不能拆成多条 Entry。

对应 [03-Lane分支管理系统](../系统设计/02-数据与存储层/03-Lane分支管理系统.md)。

```python

@dataclass
class LanePointer:

    leaf_id: str                   # 当前指向的 Entry.id
```

## 三、LLM 接口层：Message / LLMEvent

对应 [06-LLM接口层](../系统设计/03-Agent核心层/06-LLM接口层.md)。

```python
# src/llm/events.py
from dataclasses import dataclass, field
from typing import Literal, Optional, Union, List

@dataclass
class Message:
    """LLM API 请求/响应用的统一消息格式，与 Entry 是两套结构（见本文件第七节的转换关系）"""
    role: Literal["system", "user", "assistant", "tool"]
    content: Optional[str] = None
    tool_calls: Optional[List[dict]] = None     # 仅 assistant：[{id, name, arguments}]
    tool_call_id: Optional[str] = None          # 仅 tool

EventType = Literal["text_delta", "tool_call", "done", "error"]

@dataclass
class LLMEvent:
    type: EventType
    data: dict

# data 的形状按 type 区分：
# text_delta -> {"text": str}
# tool_call  -> {"id": str, "name": str, "arguments": dict}
# done       -> {"stop_reason": str, "usage": {"prompt_tokens", "completion_tokens", "total_tokens"}}
# error      -> {"error": str, "message": str, "retryable": bool}
```

## 六、错误类型：AgentError 体系

对应 [08-错误处理机制](../系统设计/04-支撑模块/08-错误处理机制.md)。

```python
# src/errors/types.py
from dataclasses import dataclass, field
from typing import Optional, List

@dataclass
class AgentError(Exception):
    message: str
    code: str
    details: Optional[dict] = None
    suggestions: Optional[List[str]] = None

@dataclass
class ToolExecutionError(AgentError):
    tool_name: str = ""
    tool_args: dict = field(default_factory=dict)

@dataclass
class PermissionDeniedError(AgentError):
    tool_name: str = ""
    permission_level: str = ""
    reason: str = ""

@dataclass
class ValidationError(AgentError):
    tool_name: str = ""
    validation_errors: List[str] = field(default_factory=list)

@dataclass
class LLMAPIError(AgentError):
    provider: str = ""
    retryable: bool = False
    retry_after: Optional[int] = None

@dataclass
class SystemError(AgentError):
    source: str = ""
    traceback: str = ""
```

不引入独立的 `Result[T, E]` 泛型类型（[08 号文档](../系统设计/04-支撑模块/08-错误处理机制.md) 三节提到的 `Ok`/`Err` 是概念性示例）——Python 生态里 `try/except` + 显式异常类型已经是惯用法，重新发明 `Result` 类型会与工具层大量使用的 `async/await` 语义冲突（`async` 函数天然靠异常传播错误，包一层 `Result` 反而要在每个 `await` 点手动判断，得不到类型安全的实际收益）。这是唯一一处代码设计与功能设计文档字面示例不同的地方，原因写在这里以备核查。

## 八、Entry ↔ Message 的转换关系

`Entry`（树节点，落盘格式）和 `Message`（LLM API 格式，请求用）是两套独立的数据结构，不能混用同一个类型——这是刻意的分层：`Entry` 要携带 `parent`/`lane`/`seq` 这些树结构信息，`Message` 只关心 LLM 协议要求的字段。转换发生在 `MessageProvider.get_context()` 内部（见 [03-核心模块与类设计](03-核心模块与类设计.md) 二节）：

```python
def entry_to_message(entry: Entry) -> Message:
    if entry.role == "assistant" and isinstance(entry.content, list):
        text_parts = [b for b in entry.content if isinstance(b, str)]
        tool_uses = [b for b in entry.content if isinstance(b, ToolUseBlock)]
        return Message(
            role="assistant",
            content="".join(text_parts) or None,
            tool_calls=[{"id": t.id, "name": t.name, "arguments": t.arguments} for t in tool_uses] or None,
        )
    if entry.role == "tool" and isinstance(entry.content, list):
        # 一个 Entry 可能打包多个 ToolResultBlock；转换成多条 tool Message，
        # 因为 OpenAI/DeepSeek 协议要求每个 tool_call_id 对应独立一条 role=tool 消息
        return [Message(role="tool", content=b.content, tool_call_id=b.tool_call_id)
                for b in entry.content if isinstance(b, ToolResultBlock)]
    return Message(role=entry.role, content=entry.content)
```

**关键点**：一个打包了多个 `ToolResultBlock` 的 `Entry`（树上一个节点），转换到 LLM 协议层时会**展开成多条** `role=tool` 的 `Message`——这是协议要求（每个 `tool_call_id` 必须有对应的 `tool` 消息），不违反 [02 号文档](../系统设计/02-数据与存储层/02-树形对话历史系统.md) 2.2 节"一次打包写入"的规则,那条规则约束的是**树物理存储**的节点数,不约束发给 LLM 时的协议层展开方式。
