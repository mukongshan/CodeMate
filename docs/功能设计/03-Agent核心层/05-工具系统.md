# 工具系统

> 当前实现基线：2026-09-02

---

## 一、当前实现

工具系统由三层组成：

1. `Tool` 抽象基类
2. `ToolRegistry`
3. 具体工具实现

当前工具的统一返回类型是 `ToolResult`，不是拆分成单独的成功 / 失败类型。

---

## 二、ToolResult

```python
class ToolResult:
    content: str
    is_error: bool
    metadata: dict
    suggestions: list[str] | None
```

规则：

- `content` 是喂给 LLM 的主文本
- `is_error=True` 时，`to_llm_text()` 会把建议一起带上
- `metadata` 只给前端 / 日志，不进入上下文

---

## 三、Tool 基类

`Tool` 只负责暴露元数据和执行接口：

- `name`
- `description`
- `parameters`
- `permission_level`
- `execute()`

`permission_level` 实际上来自 `TOOL_PERMISSIONS`，不是工具自己随意决定的属性。

---

## 四、ToolRegistry

`ToolRegistry` 负责：

- 注册工具
- 暴露 JSON Schema
- 校验参数
- 调用 `execute()`

权限检查不放在 `ToolRegistry` 内部，而是在 `Agent._execute_tool_calls()` 统一做。

---

## 五、内置工具

当前内置工具的大致边界是：

| 工具 | 级别 | 说明 |
|---|---|---|
| `read_file` | SAFE | 读文件 |
| `glob` | SAFE | 文件匹配 |
| `grep` | SAFE | 文本检索 |
| `list_directory` | SAFE | 列出当前工作区目录 |
| `write_file` | WRITE | 写文件 |
| `edit_file` | WRITE | 编辑文件 |
| `bash` | DANGEROUS | 命令执行 |
| `delegate_task` | SAFE | 子 Agent 委托 |
| `web_search` | SAFE | 联网搜索 |
| `web_fetch` | SAFE | 获取公共 HTTP(S) 页面 |

主 Agent 默认注册以上 9 个工具；子 Agent 使用只读子集并额外受深度和超时限制。`bash` 只是一层参数转发，真实限制都在权限门禁和 `run_command()`。

---

## 六、bash 工具

`BashTool` 现在委托给 `backend/src/tools/exec_tool.py` 的 `run_command()`。

它不直接做权限判断，主要依赖：

- `PermissionManager`
- `inspect_command_safety()`
- `is_command_blacklisted()`
- `subprocess` 执行约束

---

## 七、文件工具

文件工具在自身入口还会做 workspace 边界校验。

- 读取只能读 workspace 内
- 写入不能越过 workspace
- 系统关键路径直接拒绝

这层约束和权限门禁是叠加的，不是互相替代。

---

## 八、子 Agent

`delegate_task` 复用父 Agent 的同一个 `PermissionManager`。

也就是说，子 Agent 不是权限豁免区，只是一个额外的执行上下文。
