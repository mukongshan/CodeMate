# 12 - 存储层设计

> 当前实现基线：2026-09-02

## 一、职责边界

存储层负责把 Workspace、Session、Lane、Entry、Git 元数据和结构化日志落到本地文件，并在重启后恢复可用状态。它不负责 Agent 决策、权限判定和 UI 布局。

当前采用三种文件语义：

| 语义 | 格式 | 适用内容 |
|---|---|---|
| 当前状态 | JSON | Workspace 注册表、Session 元数据、Git Binding |
| 追加事实 | JSONL/NDJSON | Entry、Lane 更新、检查点、Git 操作、日志 |
| 临时恢复记录 | JSON | Session 删除 Journal |

## 二、目录组织

```text
{DATA_DIR}/
├── workspaces/
│   ├── registry.json
│   └── {workspace_id}/sessions/{session_id}/
│       ├── session.json
│       ├── conversation/entries.jsonl
│       ├── lanes.jsonl
│       ├── git/bindings.json
│       ├── git/checkpoints.ndjson
│       ├── git/operations.ndjson
│       └── logs/
└── deletions/*.json
```

`SessionPaths` 是目录结构的唯一组装入口。新代码不再使用 `{session_id}.jsonl` 等全局扁平文件名；这些文件只由显式旧数据迁移逻辑读取。

## 三、Workspace 注册表

`registry.json` 当前版本为 `1`，包含：

| 字段 | 说明 |
|---|---|
| `version` | 注册表格式版本 |
| `workspace_order` | Workspace 展示顺序 |
| `workspaces` | `workspace_id → WorkspaceRecord` 映射 |
| `pending_mutation` | 注册表变更恢复信息，当前保留兼容字段 |

WorkspaceRecord 保存稳定 ID、规范绝对路径、标题、Session ID 列表和时间。加载时会验证 Workspace 记录格式，并依据 Session 元数据中的 `workspace_id` 与规范路径重新校验归属。注册表损坏时先备份，再从 Session 元数据重建可识别记录。

注册表写入采用临时文件、`flush`、`fsync` 和 `os.replace`。工作区移除只改注册表，不删除用户目录。

## 四、Session 元数据

`session.json` 至少保存以下信息：

| 字段 | 作用 |
|---|---|
| `workspace_id` / `workspace` | 校验 Session 归属 |
| `session_id` | Session 稳定身份 |
| `workspace_title` | 创建时的工作区展示信息 |
| `title` | Session 展示标题 |
| `title_source` / `title_locked` / `title_updated_at` | 标题来源和自动命名控制 |
| `command_blacklist` | 当前 Session 的命令黑名单 |
| `created_at` / `updated_at` | 生命周期时间 |

旧 Session 缺少标题字段时分别回退到 Session ID、`default`、`false`；旧 Lane 缺少展示字段时回退到 slug。

## 五、Entry JSONL

### 5.1 Entry 结构

`conversation/entries.jsonl` 每行是一个 Entry：

| 字段 | 说明 |
|---|---|
| `id` | 节点 ID |
| `parent` | 父节点 ID，根节点为空 |
| `lane` | 追加时活跃 Lane 的静态标签，不用于路径判断 |
| `seq` | SessionStorage 分配的递增序号 |
| `role` | `user`、`assistant` 或 `tool` |
| `content` | 字符串或结构化 block 列表 |
| `entry_type` | 普通消息或 `compaction` 等特殊类型 |
| `metadata` | 工具、压缩和文件变更等附加信息 |
| `reasoning_content` | 可选推理内容 |

结构化 block 使用 `text`、`tool_use`、`tool_result` 三种 kind。一次 assistant 并行调用多个工具时，结果必须打包在一条 role=tool Entry 中，保证每个节点只有一个 parent。

### 5.2 加载与索引

SessionStorage 启动时一次性读取有效行，建立：

- `_entries: id → Entry`；
- `_children_index: parent → child ids`；
- `_lane_index: lane → entry ids`；
- `_next_seq`。

所有路径、子节点、公共祖先和分叉查询只使用内存索引，不在请求路径上重新扫描 JSONL。重复 ID、缺少字段、JSON 损坏和未知 block 会跳过并记录 warning；最后一条半写入行等价于本次追加未发生。

### 5.3 写入与查询

追加 Entry 时先读取当前 Lane 的 `leaf_id` 作为 parent，再写入 Entry，最后推进 Lane 指针。SessionStorage 用单 Session 写锁串行化追加。主要查询为：

| 方法 | 作用 |
|---|---|
| `get_all_entries()` | 按 seq 返回全部节点，用于快照 |
| `get_history_path(leaf_id)` | 沿 parent 从叶到根，再反转为根到叶 |
| `find_common_ancestor(a, b)` | 求最近公共祖先 |
| `get_children(id)` | 查询直接子节点 |
| `get_context_window(leaf_id)` | 取预算内上下文并修复开头孤立 tool |

## 六、Lane JSONL

`lanes.jsonl` 是 append-only 流水，物理文件中同一 Lane 可以出现多次。重启时必须重放全部记录，以最后一次有效状态为准；不能因为物理最后一行属于另一个 Lane 就只读取最后一行。

LanePointer 当前字段为：

| 字段 | 说明 |
|---|---|
| `lane_id` | 稳定 Lane 身份 |
| `lane` | kebab-case slug、API 路径和 Git 标识 |
| `leaf_id` | 对话树叶子 |
| `created_from` | 创建血缘展示字段 |
| `description` | 方案意图 |
| `display_name` | 用户展示名称 |
| `name_source` | `manual`、`auto` 或 `fallback` |
| `archived` | 是否归档 |

另有 `{"current_lane": "..."}` 记录保存 Session 最近离开的当前 Lane。main Lane 在新 Session 中始终存在，空树时 `leaf_id=null`。

## 七、Git 存储

`git/bindings.json` 保存 Lane 与托管分支、Worktree、HEAD、发布信息、待检查点状态的当前绑定；`checkpoints.ndjson` 记录代码检查点；`operations.ndjson` 记录创建、发布、集成和恢复等操作状态。Git 的文件资源本身由 Git 仓库维护，CodeMate 只保存映射和操作事实。

自动检查点可以合并多个成功 Run，触发条件包括空闲窗口、最大等待时间、待处理 Run 数和变更文件数。敏感文件、超大文件、冲突或外部 ref 改写会阻断或降级检查点，不把检查点当作测试通过或正式发布。

## 八、删除 Journal

Session 删除前在 `deletions/` 写入 Journal，记录 `prepared`、`git_cleaned`、`failed` 等状态以及可恢复阶段。Git 资源清理和 Session 目录删除不是一个不可恢复的原子系统调用，因此启动时会扫描 Journal：已完成 Git 清理的操作可自动继续删除目录，无法判断安全边界的操作保留日志。

删除幂等性要求：

- 不重复删除其他 Session 的目录；
- 不递归删除用户源工作区；
- 不自动删除已发布普通 Git 分支；
- 中途失败时留下足够信息供重试。

## 九、旧数据迁移

迁移器把旧 `data/sessions/` 中的 JSONL、Git 元数据和 Session 元数据复制到新分级目录，完成大小校验和元数据写入后才删除旧文件。迁移默认不在启动时自动执行：先通过 `GET /api/storage/legacy-migration` 查看计划，再通过 `POST` 明确执行。

## 十、容量与安全边界

JSONL 适合当前单用户、单 Session 追加历史；启动时全量加载意味着超长会话会增加内存压力，因此上下文窗口用估算 token 预算截取，记忆模块可以生成 `compaction` Entry。文件读取上限为 1 MB，搜索单文件上限为 512 KB，目录列表上限为 500 项；这些是工作台 API 限制，不改变 Agent 工具的独立限制。

所有文件路径在业务层解析后必须位于当前 Lane 工作区；`.git` 元数据不允许通过工作台文件接口搜索或修改。文件保存使用临时文件替换，并以 SHA-256 `expected_revision` 防止覆盖外部修改。
