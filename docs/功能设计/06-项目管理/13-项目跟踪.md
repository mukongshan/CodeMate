## 二、当前可演示闭环

1. 选择或创建本地 Workspace。
2. 创建或打开 Session，自动拥有 `main` Lane。
3. 提交编程任务，观察 Agent 流式回复、工具调用、权限请求和文件审查。
4. 在资源管理器打开文件，编辑已有文本并按版本摘要安全保存。
5. 打开当前 Lane 终端，执行受权限和工作目录限制的命令。
6. 创建、切换和重命名 Lane，比较对话和代码 Diff。
7. 通过检查点恢复、丢弃、发布或按策略集成代码。
8. 刷新或重启后从快照和 JSONL 恢复 Workspace、Session、Lane 与历史。

## 三、验证基线

源码级验证应覆盖：

- `backend/tests/test_workspace_storage.py`：迁移、损坏注册表和 Session 归属；
- `backend/tests/test_workbench_backend.py`：文件保存冲突、搜索、文件回滚和普通 Git 操作；
- `backend/tests/test_naming.py`：标题降级、候选过滤和 Lane 元数据重放；
- `backend/tests/test_checkpoint_strategy.py`、`test_version_control.py`：检查点和 Git 生命周期；
- `web-ui/src/__tests__/`：Session Picker、工作台、工具卡片、文件审查、Toolbar、WebSocket 和 Lane 弹窗。

当前文档更新只修改 `local_docs`，不代替代码测试；代码测试应以实际命令输出为准，不复用旧报告中的覆盖率数字。

## 四、未完成或明确不做

### 4.1 当前未实现

- 完整 IDE 语言服务：语法高亮、补全、诊断、跳转和格式化；
- 编辑器中新建、重命名、删除文件和多文件替换；
- 完整 Git 客户端：远程推送、rebase、cherry-pick、复杂冲突编辑器；
- 多终端标签、终端历史持久化和远程终端；
- 移动端布局和布局跨刷新持久化；
- 面向用户的独立日志检索 UI。

### 4.2 明确不做

- Docker 容器沙箱；
- 把子 Agent 中间消息写入父 Session 树；
- 用用户可读名称直接作为 Git 分支路径；
- 启动时静默迁移旧数据；
- Workspace、Session 或 Lane 删除时递归删除用户源目录；
- 把内部检查点或 Agent 完成状态宣称为测试通过或正式发布。
