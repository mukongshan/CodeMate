# 14 - 技术决策与取舍

> 当前实现基线：2026-09-02

## 一、核心决策

### 1. 树形 Entry，而不是线性消息

每条用户、assistant 或 tool message 都是 Entry，`parent` 是树结构唯一来源。Lane 只保存叶子指针，因此可以从历史任意节点创建新方案，而不复制公共祖先，也不破坏旧路径。

### 2. Workspace、Session、Lane 分级

本地项目目录、一次连续工作和一次方案实验拥有不同生命周期，不能用一个平铺 Session 文件名替代。Workspace 用稳定 UUID 和规范路径注册；Session 用独立目录保存日志和元数据；Lane 在 Session 内管理对话叶子和可选代码 Worktree。

### 3. JSON/JSONL，而不是数据库

当前数据规模是本地单用户、追加为主的对话和操作记录。JSONL 可读、适合崩溃恢复和演示；内存索引承担查询性能。需要原子覆盖的注册表和当前状态使用 JSON。未来数据量或查询维度显著扩大时再评估 SQLite。

### 4. REST + WebSocket 分工

CRUD、文件读取保存、Git 查询和管理操作走 REST；Agent 流式事件、权限响应、运行中断和终端双向 I/O 走 WebSocket。进入 Session 先取快照再接事件，避免建连期间丢节点。

### 5. Permission Gate + 进程约束，而不是 Docker

当前威胁模型集中在本地 Agent 的错误操作。安全边界由工具风险级别、命令黑名单、命令结构检查、Workspace 路径校验、参数化进程、固定 cwd、输出捕获和超时构成。容器会引入额外部署和调试依赖，当前不采用。

## 二、实现中的简化

### 2.1 Lane/Git 只覆盖本地核心闭环

已实现检测、托管分支、独立 Worktree、检查点、状态、Diff、stage/unstage/commit、发布、归档和有限策略集成；不实现远程推送、rebase、cherry-pick、平台账号和完整冲突编辑器。CodeMate 不自动删除已发布普通分支。

### 2.2 编辑器只做安全文本保存

工作台支持已有文本文件的读取和保存，使用 SHA-256 revision 防止外部修改覆盖；不冒充完整 IDE，不支持新建文件、二进制保存、语言服务和多文件替换。

### 2.3 终端只做当前 Lane 的受限交互

终端复用 Session WebSocket，但每个进程绑定当前 Lane 工作目录，输入再次通过 bash 权限检查。Windows 优先 WSL，回退 PowerShell；不提供远程终端、多用户共享或终端持久化。

### 2.4 子 Agent 只返回摘要

子 Agent 采用独立内存 Provider，只读工具子集和深度限制。中间过程通过实时进度展示，最终以摘要 ToolResult 返回父 Agent，不污染父树。

### 2.5 智能命名必须可失败

Session 标题和 Lane 建议使用无工具 NamingService；LLM 输出必须经过清洗、长度限制和 slug 校验。LLM 失败时采用本地 fallback，命名不能改变 Agent Run 结果，也不能覆盖手动锁定标题。

## 三、明确放弃

- RAG、向量数据库和项目级长期知识库；当前只保留项目指令文件加载和会话上下文压缩。
- MCP、插件市场和复杂 Skills 引擎。
- 完整实时日志查询 UI；前端展示 WebSocket 运行事件，结构化日志服务调试。
- 移动端优先布局、跨刷新工作台布局同步。
- 启动时自动迁移旧数据；迁移必须先预览、再显式执行。

## 四、未来扩展约束

未来增加能力时必须遵守：

1. 不改变 `Entry.parent` 的树语义和工具结果打包规则。
2. 不把展示名称替代 `lane` slug、`lane_id` 或 Git 标识。
3. 不让 Workspace/Session/Lane 生命周期操作触碰用户源目录。
4. 不绕过 Session 级运行锁、权限门禁和当前 Lane 工作区检查。
5. 新增持久化内容先明确事实记录还是当前状态，再选择 JSONL 或 JSON。
